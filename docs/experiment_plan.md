# 最小实验与验收协议 v0.1

阶段门控：先测量，再决定规模；以下模型与参数是候选，不是已验证的训练配置。先做英文文本 Retail 自定义子集，尽量沿用官方环境。

## 顺序、输入输出与理解目标

| 阶段 / 为什么做 | 输入 | 输出 | 验收 / 核心概念 |
|---|---|---|---|
| 0 可行性与隔离（当前） | 固定源码、任务元数据、本机 | 来源锁、split、工具审计、基线 dry-run | 版本唯一、无已知跨集合实体；理解 Agent/环境/评测器边界 |
| 1 原模型 pilot | Qwen3-0.6B 原权重、规则/schema、dev | 真实轨迹、错误分类、token/费用/延迟 | 先 dev75 单任务，再 6 任务各 1 次；所有调用可重放，成功失败均计；理解部分可观测决策 |
| 2 极小 SFT | train 中实际成功且质检的 ≤16 条交互 | 标签可视检查、8 条样本过拟合、损失与 dev 回测 | assistant token 边界正确，能过拟合并生成合法调用；比较原模型，无改善就诊断；理解 teacher forcing 与 exposure bias |
| 3 最小在线 GRPO | 通过验收的 SFT checkpoint、独立训练环境 | 2 个训练任务 × 每题 4 rollout、奖励审计；再几十步训练探针 | 真正多轮、每条独立 DB/会话、生成与奖励 ID 一致、只优化 assistant token；理解组内优势与策略比率 |
| 4 对比与消融 | A 原模型 / B SFT / C SFT+GRPO | 同协议评测、失败分析、成本表、报告 | dev 选点后冻结最终测试；至少去掉流程门控的短程 dev 对照，最后全部用同一评测；理解因果对照与估计波动 |

假设每周 10–15 小时：阶段0–1 约1周；数据与SFT约1–2周；在线接入/GRPO约2周；评测复盘约1周。总约5–6周只是排期假设，GPU/模拟器可用性与适配工作可能延长；不承诺 RL 提升。

## 原模型基线运行方式

候选 Qwen/Qwen3-0.6B（[官方模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)，Apache-2.0），保留其 instruct/chat 模板，优先关闭 thinking，统一 A/B/C。模型 revision 尚未锁定：本次 HF 元数据请求失败，未下载权重；进入运行阶段先取不可变 revision。1.7B 只在 0.6B 链路打通和显存测量后评估。

复用官方 LLMAgent → LiteLLM → 本地 OpenAI-compatible inference endpoint（127.0.0.1），作为最小接入；服务仅用于采样，不建设平台。Qwen 原生工具模板/解析器必须先做 JSON 参数 → 官方 ToolCall → 工具 → 返回下一轮的往返验收。server 及 tokenizer 版本后续锁定，当前没有启动或验证推理服务。若 vLLM 常驻挤占单卡训练显存，使用同进程 Transformers rollout，保持相同模板和解析协议。

configs/baseline_plan.json 和 scripts/baseline_plan.py 固定官方 CLI 的 **dry-run**：benchmark none、英文、Retail、普通 llm_agent、显式 dev ID（75/0/1/2/3/4）、trial1、seed300、temperature0、max_steps80、max_errors3、timeout180s、并发1、每次生成512 token。80 是 orchestrator step 上限，不等同于80个 Agent 回复。候选上下文预算8192 token，先测实际 prompt/tool 长度，超限记失败或停止修订协议，不静默丢历史；服务配置须与模型上下文一起落盘。

用户模拟候选沿用固定 gpt-4.1-2025-04-14、temperature0，不预设可调用；NL 评审沿用上游固定模型，语义 communication scorer 默认由上游配置解析。适用任务会产生评审费用，不能只算 Agent token。最初只跑 dev75，因没有 NL 文本断言，便于隔离模型/工具问题。随后六任务 pilot 不代表总体成功率。真实运行入口待密钥环境、推理服务、价格与费用确认具备后添加；当前脚本无计费执行分支。

## 训练候选与停止门槛

0.6B：优先 BF16 LoRA（3060 根据实测能力选择 FP16 或 QLoRA）；r=16、alpha=32、dropout=0.05，batch1、梯度累积8、gradient checkpointing、单条完整轨迹上限先候选8192，目标模块先 q/k/v/o projections。学习率先候选1e-4，8条过拟合最多100 steps，再20–50步测资源。任何损失 NaN/模板错误/孤立工具消息/OOM 都停止。SFT 不把 tools/user/system 当目标；packing 暂关闭。正式配置根据真实长度与 dev 决定。

GRPO 先用2个 train任务、G=4、temperature0.8、每条真实多轮，单 GPU 顺序采样，避免同时驻留多个模型服务。先看8条是否有组内奖励差异；2题不足以确定普遍结论，只有混合奖励时才做30步优化探针。若全0或全1，调整训练难度/任务或SFT，重新测量，不扩大付费训练。候选起始lr5e-6、clip0.2、KL系数0.02；这些待 TRL 版本与 loss 实现确认后冻结。

使用 Transformers + PEFT + TRL；锁定版本前核验 TRL 当前多轮 rollout/custom generation 接口。环境/用户 token 是 observation，策略损失与相应 logprob 只覆盖模型真实生成的 assistant span；tool_call JSON 也属于动作。逐轮模板插入的 token 不能误算生成动作。旧策略 logprob、优势、KL、有效token mask 的形状与数值做实际检验。采样 → 环境执行 → 用户继续 → 终局奖励 → GRPO 更新才算在线 RL；固定离线答案、拒绝采样或重排不算交付。

奖励先保存官方 reward 与所有 breakdown，再做自定义流程门控。正确终局为主信号，格式/长度仅诊断或微小辅助。正式 RL 前做故意拒绝、全转人工、跳确认、错用户、额外改状态、错误参数、超时样本的反例审计。拟定 reward-v1 必须通过该审计；不能用训练奖励替代外部成功率。消融选择“同等训练预算下去掉流程门控”，在 dev 短程实验，并用同一个外部流程审计比较；预算允许增加 continued SFT 对照，避免把额外训练量当作 RL 独有效果。

## 预注册指标与最终测试

主要指标：每个任务一次交互（trial1）的任务成功率=sum(reward==1)/已计划任务数。最终为冻结 reviewed English Retail50；A/B/C 同样规则、工具、用户模型、persona、seed、上下文、step/token/timeout预算、解码方式。若任何配置变化，显式列出并将比较降为探索性。英文单格/限制预算的结果标为 RetailAlign 自定义实验，不声称完整 text-v1 官方成绩。

同报流程合规任务成功率（终局成功且认证/确认/授权均通过）、参数/归属错误、无效调用与工具异常、转人工/拒绝率、额外数据库变更；错误既报任务级 n/N，也报调用级 n/N，类别允许多标签。轨迹报告 Agent token、总输入token、用户与评审token、调用次数、step数、p50/p90长度/延迟、总费用、GPU显存峰值。失败/超时不删；外部服务故障单列，任何重跑全留记录并预先统一重跑规则。

trial1只作为成本可控初版；相同seed不保证供应商完全可复现。预算允许时对全部模型增加相同第二/第三试验，报告每任务成功次数、试验均值和波动，不把 pass@k 与单次成功率混用。单次率报告 Wilson 95%区间；差异报告配对成功表和按用户/任务家族组的 bootstrap 区间（同用户多任务不当独立样本），小组数时明确区间不稳定，可补充描述而不强调p值。6任务pilot仅调试，不作提升结论。

最终测试前冻结：model/tokenizer revision、adapter hash、checkpoint、完整协议、数据与奖励版本、用户/评审模型、预算和停止条件。选择 checkpoint 只看 dev。若公共基础模型可能预训练见过 τ-bench，报告污染限制；领域行为改善和知识能力增强必须分别举证。
