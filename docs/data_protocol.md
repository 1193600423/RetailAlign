## 自动检查的含义与限制

对历史原文与 2.0 英文替换任务同时提取用户 ID、邮箱、完整姓名、订单 ID，并通过数据库把订单关联到用户。共享任一用户/订单即归为同组。对 user_scenario 做邮箱/ID/数字归一化，字符 SequenceMatcher（autojunk=False）相似度 ≥0.80 也归组，再取传递闭包。所有接触冻结/历史 holdout 的组整体隔离。

阈值只是保守自动线索，不证明语义模板完全隔离。生成前人工检查候选与 holdout 的相似性应由独立数据审计角色完成，给训练侧仅返回批准/隔离 ID，不把测试目标发给教师或策略。当前未安排多 Agent。若无法独立审计，则扩大保守隔离或用新订单/用户/目标组合的自定义训练数据，保持最终测试封存。公共规则、工具 schema、商品目录可以共享，但不把共享目录解释成独立任务。

自定义训练场景必须：新用户/订单/付款实体；不克隆封存订单；按任务家族分组；变体继承父场景 split；先登记与校验再生成轨迹。仅替换名称、ID 或语言不能消除语义泄漏。六语言同 canonical ID 全部属于同一业务场景，不能跨集合。报告自定义与官方任务的差异，不能把派生测试当官方榜单。

## 三种可见信息

| 使用方 | 可用信息 | 禁止流入 Agent |
|---|---|---|
| Agent | policy、tool schemas、公开对话、已执行工具结果 | task description、完整 user_scenario、evaluation_criteria、参考动作、预期答案、gold DB |
| 用户模拟器 | 用户目标/已知信息/persona/用户侧历史 | 参考动作和验收标准 |
| 环境/评测器 | DB、初态、完整真实轨迹、隐藏验收信息 | 不把内部字段加入 Agent 对话或工具返回 |

不得为了让学生更容易成功，把实际用户尚未提供的目标直接写在初始提示词中。程序策略也须从公开 observation 决策；知道 reference 的 replay 只作开发者审计，不能标为成功交互数据。

## SFT 轨迹的准入条件（尚未生成）

每条记录包含 source_repo/commit、任务 ID、parent_scenario_id、split、生成者模型及 revision/参数、seed、policy/schema/hash、工具执行记录、原始轨迹、validator_version、验证项与人工复核状态。验证工具返回、参数类型/存在性/归属关系、最终 DB/必要回复、认证与明确确认、额外变更。失败/截断/异常不混入成功 SFT。

首次 ≤16 条成功轨迹全部人工审阅；扩大后按任务家族、长短、奖励类型分层至少抽查 20%（每家族至少 1 条），任何系统性错误暂停该批次。改验证器后重新验证受影响版本。写入纯 assistant 标签前检查 tokenizer 角色边界和工具 JSON；不能截掉 tool_call 后半或丢孤立 tool response，超长先隔离/保留完整交互段，不静默截断。

每版分别统计：独立官方任务数、独立实体/模板组数、自定义父场景数、派生场景数、尝试/成功/通过质检轨迹数、token p50/p90/max、重复率（精确与规范化）、动作覆盖率、人工抽样发现率。当前真实交互轨迹数 **0**，训练样本 **0**；开发者 oracle 审计不计入。

## 测试封存

最终 50 任务不可用于训练、教师生成、提示词/奖励调试、超参或检查点选择。冻结前在 dev 定协议；最终测试采用 2.0 reviewed English binding。失败测试可写最终复盘，若依据它继续修改，后续成绩标为测试知情探索结果，需要新 holdout 才能作新的确认性结论。公开任务可能已进入基础模型预训练，数据隔离不排除预训练污染。
